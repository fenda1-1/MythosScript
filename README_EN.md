## Build workflows that fit the way you play

MythosScript brings action recording, path sequences, node graphs, variables, triggers, packet analysis, profiles, and themes into one in-game workbench. Record a repeated action, refine its steps, add conditions and event-driven triggers, then inspect logs and captured packets as you improve the workflow.

| Capability | What it enables |
| :--- | :--- |
| **Actions and paths** | Combine movement, interaction, waits, inventory operations, and reusable sequences. |
| **Node graphs and triggers** | Model branches and start workflows from chat, GUI, inventory, or packet events. |
| **Variables and conditions** | Pass game state through global, sequence, local, and temporary scopes. |
| **Packet workbench** | Capture, filter, inspect, extract, intercept, and send packet data. |
| **Profiles and sharing** | Manage configurations, import and export them, and reuse setups through share codes. |
| **Themes** | Customize the workbench with colors, backgrounds, and live previews. |

## Getting started

| Requirement | Version |
| :--- | :--- |
| Minecraft | **1.12.2** |
| Forge | **14.23.5.2860** |
| Java | **8** |

1. Prepare a Minecraft 1.12.2 Forge instance running on Java 8.
2. Put one compatible MythosScript JAR in that instance's `mods` directory.
3. Launch the game and open the dashboard with the configured main-menu shortcut.
4. Start with a short recording, inspect it in the path workbench, save it, and then add variables, conditions, and triggers as needed.

See the [GitHub Releases page](https://github.com/fenda1-1/MythosScript/releases) for published versions.

## Build from source

The repository uses the Gradle Wrapper, so Gradle does not need to be installed separately. Building requires **JDK 8**. The build checks `JAVA8_HOME`, `JDK8_HOME`, and `JAVA_HOME` for a usable Java 8 installation.

From the repository root, run:

```powershell
.\gradlew.bat build
```

On Windows, `build.bat` runs the same command. The build compiles the project, remaps Forge names, and then runs ProGuard automatically. It produces these files in `build/libs/`:

| File | Purpose |
| :--- | :--- |
| `MythosScript-v1.0.71-mc1.12.2.jar` | Standard build for development and troubleshooting. |
| `MythosScript-v1.0.71-mc1.12.2-obf.jar` | ProGuard-obfuscated build, intended for distribution. |

Both are Minecraft 1.12.2 Forge mods. Install only one of them in a game instance's `mods` directory at a time. The build includes the current working tree, so confirm the local changes you intend to ship before creating a release.

To generate only the standard JAR:

```powershell
.\gradlew.bat jar reobfJar
```

To regenerate only the obfuscated JAR after the standard JAR already exists:

```powershell
.\gradlew.bat proguard
```

The ProGuard configuration is generated by the `proguard` task in `build.gradle`. It preserves Forge entry points, event handlers, GUIs, Mixins, and ShadowBaritone runtime classes and resources required for loading.
